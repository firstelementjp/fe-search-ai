# Model Evaluation Question Set

Default chat model の比較・採用判定用の手動評価セット。
デモサイト `4510m.local`（シゴトの森 / 求人データ約451件）を前提とする。

> **Note**: データ変更時は「期待投稿」の post ID を見直すこと。
> 同じ質問でも検索結果は「会話履歴を含む拡張クエリ」に左右されるため、
> モデル比較は必ず**シングルターン（毎回新規セッション）**で行う。

## Protocol

1. 各質問は**新しいシークレットウィンドウ / セッションリセット後**に1回だけ送信する。
   連続して質問すると、直前の回答文が検索クエリ拡張に混入して結果が変わる。
2. 評価中は検索設定を固定する（例: rerank OFF / BM25のみ / top_n=10）。
   別設定で評価する場合は結果シートに設定を記録する。
3. 判定は「モデルが与えられたコンテキストをどう扱ったか」を採点する。
   期待投稿が top10 に入っていない場合はモデルの責任ではないため、
   別列で「期待投稿がコンテキストに存在したか」を記録し、モデル評価と検索評価を分離する。
4. 1モデルにつき結果シート1セットを使い、モデル名と実施日を記録する。

## 判定の凡例

- `○` … 期待振る舞いを満たす
- `△` … 概ね正しいが条件違反・不親切・軽微な不正確さあり
- `×` … 幻覚（存在しない求人/URL/数値）、スコープ逸脱、明確な取り違え

## 採点観点（全問共通）

| 観点 | 見るもの |
|---|---|
| 関連性 | 期待投稿を提示できたか。条件外の投稿を無断で混ぜていないか |
| 忠実性 | リンク・数値・勤務地はコンテキストの記述通りか（創作なし） |
| 範囲遵守 | サイト外の知識・一般論に踏み出していないか |
| 対話設計 | 該当なし/曖昧な場合に次の行動（絞り込み質問・代替提示）を提案できるか |

## 合格ラインの目安

- `×` が 0 件（特に E/G 系の幻覚・スコープ逸脱は致命的）
- E 系は「正直な不見つかり」＋次の行動提案が理想。定型断りのみは△
- 「期待投稿はコンテキスト内? = No」が多い場合、それはモデルではなく
  検索側（BM25/キーワード抽出/要約インデックス）の改善対象として切り分ける
