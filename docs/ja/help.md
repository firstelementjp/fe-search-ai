# トラブルシューティング

## チャットが回答しない

まず以下を確認してください。

1. チャットプロバイダーのAPIキーが設定済みで、Providers タブの **Test** ボタンが成功すること。
2. EmbeddingプロバイダーのAPIキーが設定済みであること。
3. Qdrantストレージを有効にしている場合、エンドポイント・APIキー・コレクションが正しいこと。
4. コンテンツが同期済みであること（Sync タブで Indexed Posts が 0 より大きい）。
5. 対象ページに `[fe-search-ai]` があるか、そのページ種別・デバイスでフローティングチャットが有効になっていること。
6. 組み込みレート制限（IPあたり50リクエスト/時、サイト全体1,000リクエスト/日）に達していないこと。待つか、`fe_search_ai_rate_limit_settings` フィルターで上限を上げてください。

ブラウザのコンソールとNetworkタブも確認してください。WordPress REST エンドポイントへの失敗したリクエストから、実際のエラー（認証、タイムアウト、プロバイダーエラー）が分かることが多いです。

## 回答が適切でない

- 同期設定を変更した後はインデックスを再構築してください。
- 関連投稿が同期対象に含まれ、公開されているか確認します。
- 元コンテンツのタイトルと見出しを改善します。
- 利用可能ならCohereリランクを有効化します。
- システムプロンプトと Site Purpose を調整します。
- Sync タブの **Keyword Token Count Missing** を確認 — 非ゼロならそのチャンクではBM25が機能していないので **Rebuild Index** を実行します。
- Retrieval Trace Persistence または Debug Mode を有効にして、`source_counts` とアイテムごとのスコアを見れば、ベクトル検索とキーワード検索のどちらが機能していないか判断できます。

## 同期が失敗する

- Batch Size を下げてください（Sync タブ）。
- サーバーのメモリとタイムアウト制限（`memory_limit`、`max_execution_time`）を確認します。
- プロバイダーのAPIクォータを確認します。
- Qdrantコレクションが存在し、ベクトルサイズがEmbeddingモデルと一致しているか確認します（後述）。

### 「Sync settings have changed」

保存された同期設定ハッシュと現在の設定が異なると、スマート同期は実行を拒否します。同期対象など関連設定の変更後は正常な動作です。**Rebuild Index** を一度実行して新しい設定を適用してください。

### 同期が途中で中断した

最終同期タイムスタンプは全バッチ完了後にのみ書き込まれます。**Rebuild Index** が中断した場合は、再度 Rebuild Index を実行してください — 開始時にインデックスは空にされているため、**Sync Changes** の再実行では欠落分は埋まりません。中断した **Sync Changes** はそのまま再実行できます。

### スマート同期で「処理対象なし」になる

- スマート同期は前回完了した同期以降に変更された投稿のみを処理します。**Delete Synced Data** などでインデックスを消した場合は **Rebuild Index** を実行してください。
- 一度も同期が完了していない場合、スマート同期には基準がありません — 先に **Rebuild Index** を実行してください。

## Qdrant のエラー

- **認証エラー（401/403）**: APIキー、およびエンドポイントURLのクラスターに属するキーかを確認してください。
- **コレクションが見つからない（404）**: 先にQdrant側でコレクションを作成してください。プラグインは既存コレクションへの書き込みのみ行います。
- **ベクトルサイズ不一致**: コレクションの次元数はEmbeddingモデルの出力サイズと一致している必要があります。Embeddingプロバイダーを切り替えた場合（例: OpenAI ↔ Google）は、正しい次元で新しいコレクションを作成し、Collection Name を更新して **Rebuild Index** を実行してください。
- Qdrant Cloudの**無料**クラスターは、一定期間アクセスがないとコレクションが削除されることがあります。しばらく使っていなかった後に同期・検索が突然失敗した場合はクラスターを確認してください。

## APIキーテストが失敗する

- キーに余分な空白がないか確認します。
- プロバイダーのアカウントの課金・クォータ状態を確認します。
- 選択したモデルがアカウントで利用可能か確認します。
- プロバイダーのダッシュボードのログを確認します。

## 日本語の検索品質が悪い

- サイトロケールとトークナイザー設定を確認します（Advanced settings タブ）。
- TinySegmenter は PHP 8.0 以上が必要です。それ未満のPHPではYahoo! MA APIが使われ、エンジン選択は無効化されます。
- TinySegmenter で不十分な場合は Yahoo! JAPAN 日本語形態素解析API を試してください。
- 重要な語句はページタイトルや見出しに明示的に含めてください。
- トークナイザー変更後は **Rebuild Index** を実行してください — 新しいエンジンでキーワードインデックスを構築し直す必要があります。

## ログの確認場所

| ツール                    | 場所                                                                  | 内容                                                             |
| ------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Debug Mode のシステムログ | `{prefix}fe_search_ai_system_logs` テーブル（Advanced settings タブ） | 動作イベント、retrieval traceスコア、エラー — 会話本文は含まない |
| Retrieval trace           | `{prefix}fe_search_ai_retrieval_traces` / `_items`（任意の永続化）    | ハッシュ化されたクエリ、投稿ID、ソース別スコアとランク           |
| WordPress デバッグログ    | `wp-content/debug.log`                                                | PHPエラーとプラグインの `error_log` 出力                         |
| ブラウザコンソール        | DevTools                                                              | フロントエンドのJSエラーと失敗したRESTリクエスト                 |
