# 設定

設定画面（管理メニューの **FE Search AI**）はタブで構成されています。このページは無料版の各タブのフィールドリファレンスです。Pro版では「モデル」タブと「セキュリティ」タブ、および追加フィールドが加わります。

- **プロバイダー** — APIキーとモデルプロバイダーの選択
- **同期** — インデックス対象コンテンツ、保存先、同期コントロール
- **プロンプト** — サイト情報と基本システムプロンプト
- **表示** — フローティングチャット、埋め込み、外観
- **プライバシー** — データ取扱いのサマリーと法律文書リンク
- **詳細設定** — リランカー、Qdrant、トークナイザー、ログ、データ管理

## 「プロバイダー」タブ

### API キー

プロバイダーごとに1つのパスワードフィールドがあります。キーは暗号化されてデータベースに保存されます。各行には「テスト」ボタンがあり、実際のAPIコールでキーを検証でき、現在使用中のモデルも表示されます。

| プロバイダー       | 用途                    | デフォルトモデル            |
| ------------------ | ----------------------- | --------------------------- |
| OpenAI (GPT)       | チャット補完とEmbedding | `gpt-5.4-mini`              |
| Anthropic (Claude) | チャット補完            | `claude-haiku-4-5-20251001` |
| Google (Gemini)    | チャット補完とEmbedding | `gemini-2.5-flash`          |
| Cohere (Rerank)    | 検索結果のリランク      | `rerank-v3.5`               |

モデル選択はPro版の機能です。無料版では各プロバイダーのデフォルトモデルが使われます。

**Pro版でこの表に追加される項目:**

- **DeepSeek** — 専用APIキーとテストボタンを持つ追加チャットプロバイダー。デフォルトでは非表示で、`fe_search_ai_show_deepseek_provider` フィルターで有効化します。
- **Custom Endpoint (Chat)** — OpenAI互換のチャット補完エンドポイント（例: ローカルLLMサーバー）。エンドポイントURLと任意のAPIキー。
- **Custom Endpoint (Embedding)** — OpenAI互換のEmbeddingエンドポイント（例: セルフホストモデル向け `http://localhost:11434/v1/embeddings`）。「ベクトル化 AI」の選択肢に「Custom (OpenAI-Compatible)」が追加されます。

API使用量を守るためのレート制限が組み込まれています: **IPアドレスあたり1時間50リクエスト**、**サイト全体で1日1,000リクエスト**。`fe_search_ai_rate_limit_settings` フィルターで変更できます（[開発者向けフック](hooks.md)を参照）。

### チャット AI

回答を生成するプロバイダー: OpenAI、Anthropic、Google から選択します。

### ベクトル化 AI

コンテンツと質問をEmbeddingベクトルに変換するプロバイダー: OpenAI（`text-embedding-3`）または Google（`text-embedding-004`）。ベクトル化 AI がQdrantコレクションに必要なベクトル次元を決定するため、変更時は対応するコレクションと再インデックスが必要です。

### リランク AI

リランクに使うプロバイダー。無料版ではCohereのみ対応。Cohere APIキーが必要です（「詳細設定」タブの「リランカー設定」も参照）。

## 「モデル」タブ（Pro）

Proライセンスが有効な場合に表示されます。プロバイダーごとにプリセットモデルのドロップダウンと、プリセットを上書きするカスタムモデル名フィールドがあります。

| フィールド                      | プリセット                                                             |
| ------------------------------- | ---------------------------------------------------------------------- |
| **OpenAI (GPT) Model**          | `gpt-5.4-mini`（デフォルト）、`gpt-5.4`                                |
| **Anthropic (Claude) Model**    | `claude-haiku-4-5-20251001`（デフォルト）、`claude-sonnet-4-6`         |
| **Google (Gemini) Model**       | `gemini-2.5-flash`（デフォルト）、`gemini-2.5-pro`                     |
| **Cohere Rerank Model**         | `rerank-v3.5`（デフォルト）、`rerank-v4.0-fast`、`rerank-v4.0-pro`     |
| **Custom chat model name**      | Custom Endpoint (Chat) に送るモデルID。                                |
| **Custom embedding model name** | Custom Endpoint (Embedding) に送るモデルID（例: `nomic-embed-text`）。 |

**DeepSeek Model** の行（`deepseek-chat`、`deepseek-coder`）は `fe_search_ai_show_deepseek_provider` フィルターが有効な場合のみ表示されます。

埋め込みモデルを変更するとベクトル次元が変わります。「ベクトル化 AI」の注意書きを参照し、変更後はインデックスを再構築してください。

## 「同期」タブ

インデックスの仕組み全体は[同期システム](sync.md)を参照してください。

### 同期させるコンテンツ

#### 同期ターゲット

公開投稿タイプごとに1エントリのアコーディオンです（attachmentは除外）。各投稿タイプで以下を設定します。

- アコーディオン見出しの **有効化チェックボックス** — 投稿タイプを同期対象に含めます（postとpageはデフォルトで有効）。
- **チャンクデータに含める** — インデックスに含めるフィールド: 投稿タイトル、投稿本文、投稿日、投稿者、および各公開タクソノミー。
- **Custom Fields (Post Meta)**（Pro） — チェックボックスと、チャンクデータに含めるメタキーのテキストエリア（カンマまたは改行区切り）。ACF等のカスタムフィールドに重要なコンテンツがある場合に有効です。
- **タクソノミー設定** — タクソノミーごとに「特定のターム ID のみチャンクに含める」か「特定のターム ID をチャンクから除外する」を選び、カンマ区切りのターム IDを入力します。空欄の場合は全タームが対象です。

「チャンクデータに含める」の項目が1つもチェックされていない投稿タイプは、同期時にスキップされます。

#### 特定の投稿のみを同期する

カンマ区切りの投稿ID。設定するとこれらの投稿のみが同期され、投稿タイプのルールは無視されます（各投稿タイプのメタデータ設定自体は適用されます）。

#### 特定の記事を除外

カンマ区切りの投稿ID。投稿タイプのルールに合致してもスキップされます。

#### データ保存先

チャンクとベクトルの保存先をチェックボックスで選択します。

- **WordPress database** — `{prefix}fe_search_ai_vectors` と `{prefix}fe_search_ai_keyword_index` にBM25キーワードインデックスを構築。外部サービス不要。
- **Qdrant (external vector database)** — ベクトルによる意味検索。「詳細設定」タブのQdrant接続設定が必要です。

#### ハイブリッド検索

有効（デフォルト）の場合、WordPressキーワードインデックスとQdrantベクトル検索を組み合わせ、Reciprocal Rank Fusionで融合します。**両方**のストレージが必要です。

#### 要約から埋め込みを生成

有効（デフォルト）の場合、各チャンクをまずチャットプロバイダーで構造化サマリー（トピック・事実・エンティティ・キーワード）に変換し、生テキストではなくサマリーをベクトル化します。幅広い質問へのマッチングが改善する傾向がありますが、同期時のAPIコールが増えます。

#### 同期上限

同期する投稿数の上限。最新の投稿から数えます。デフォルト `100`、`-1` で全対象投稿を同期します。お試し同期やコスト抑制に使います。

#### バッチサイズ

1回のAJAXバッチで処理する投稿数。デフォルト `10`、範囲1–100。共有サーバーでは小さい値でタイムアウトを避け、速く終わらせたい場合は大きくします。

### チューニング（Pro）

Proライセンスが有効な場合、「同期」タブの末尾に「Tuning」セクションが追加されます。

#### カスタムストップワード（キーワード検索）

カンマ区切りで指定した語をキーワードインデックスと検索クエリのトークン化から除外します。**BM25キーワード検索のみ**に作用し、埋め込み・ベクトル検索には影響しません。

- 言語別の内蔵リストは常に適用されます。**View Default Stop Words** で確認でき、再登録は不要です。
- 登録語はマージ前に正規化されます: 日本語は半角化＋小文字化、その他の言語は小文字化。個別の正規化は `fe_search_ai_normalize_custom_stop_word` フィルターで変更できます。
- サイト内のどこにでも出現し、キーワードランキングを悪化させる語（例: 自社の社名・製品名）の除外に有効です。
- 変更後は **インデックスを再構築** を実行し、新しいストップワードを除いたキーワードインデックスを作り直してください。

開発者は `fe_search_ai_stop_words` フィルターで実効リストをプログラムから変更することもできます（[開発者向けフック](hooks.md)参照）。

### 同期コントロール

インデックスの状態と同期ボタン — [同期システム](sync.md)を参照してください。

## 「プロンプト」タブ

| フィールド                 | 説明                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **サイト名（AI）**         | AIが認識するサイト名。`{site_name}` プレースホルダーに挿入されます。空欄ならサイトタイトル。                                           |
| **サイトの目的（AI）**     | サイトが提供する内容とユーザーの目的。`{site_purpose}` プレースホルダーに挿入されます。空欄ならキャッチフレーズ。                      |
| **基本システムプロンプト** | チャットモデルに送る指示文全体。空欄なら標準プロンプト。`{site_name}`、`{site_purpose}` などのプレースホルダーが実行時に展開されます。 |
| **構造化出力**             | 対応するプロバイダーでJSON構造化出力を要求。非対応なら通常テキストにフォールバック。デフォルトはオフ。                                 |

「サイトの目的（AI）」の記述例（求人サイトの場合）:

```text
このサイトは求人情報サイトです。
主なコンテンツは求人です。

各コンテンツには、以下のメタデータが含まれている場合があります：
- 地域（都道府県、海外）
- 業種
- 雇用形態（アルバイト、正社員、業務委託、派遣など）
- 給与・報酬
- キーワード・タグ

ユーザーは主に自身の希望条件に合う求人を見つけるために質問します。
関連する場合は、メタデータを使って検索結果を絞り込み、比較し、要約してください。
```

サイトのコンテンツ種別・含まれるメタデータ・ユーザーの典型的な目的を書くと、検索結果の解釈精度が上がります。

### プロンプトのプレースホルダー

システムプロンプト内のプレースホルダーはリクエスト時に展開されます。

| プレースホルダー    | 展開される値                                                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{site_name}`       | サイト名（AI）、未設定ならサイトタイトル。                                                                                                                                         |
| `{site_purpose}`    | サイトの目的（AI）、未設定ならキャッチフレーズ。                                                                                                                                   |
| `{site_url}`        | サイトURL。                                                                                                                                                                        |
| `{user_question}`   | 訪問者の質問（PII・禁止ワードの前処理後）。                                                                                                                                        |
| `{context_content}` | 検索で取得したコンテンツチャンク（各項目に `Title` / `URL` / `Metadata` / `Content`）と、リンクされた法的文書。一致なしの場合は `[No relevant information found for this query]`。 |

標準プロンプトは、検索結果のみを根拠に回答し、結果をMarkdownリンクとして引用し、情報が見つからない場合はその旨を告げ、質問と同じ言語で回答するようモデルに指示します。展開後のプロンプト全体は `fe_search_ai_final_system_prompt` フィルターで変更できます（[開発者向けフック](hooks.md)参照）。

### モデル別カスタムプロンプト（Pro）

チャットプロバイダーごとに1つのテキストエリアを持つアコーディオンです（OpenAI、Anthropic、Google、Custom OpenAI互換、有効時はDeepSeek）。そのプロバイダーに対してのみ基本システムプロンプトを上書きし、空欄の場合は標準プロンプトにフォールバックします。モデルごとの癖に合わせた指示調整に使います。

### 全画面ページ（Pro）

「表示」タブ末尾に追加されるページ選択ドロップダウンです。固定ページを選択すると、そのページへのアクセス時にチャットUIが全画面で直接表示されます。フローティングバブルを使わない「AIと話す」専用ページを作れます。

## 「プライバシー」タブ

- **現在のデータ取り扱い** — 現在有効な送信先（どのサービスが訪問者入力を受け取るか）、各レコード種別のサーバー保持期間、診断ログの有効状態を一覧表示します。
- **法律文書** — チャットのプライバシー通知に表示する利用規約・プライバシーポリシーのページ。プライバシーポリシーのページ未選択の場合、WordPress標準のプライバシー設定のページが使われます。

データ処理の全体像は[プライバシーとデータの取扱い](privacy.md)を参照してください。

### ユーザー同意（Pro）（User Consent (Opt-in)）

チャット利用前に訪問者へ同意を求めるオプトイン層です。

| フィールド                                   | デフォルト   | 説明                                                                                                                                  |
| -------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 初回利用時に同意を求める                     | オフ         | チャット使用前に利用規約・プライバシーポリシーへの同意を求めます。上記の法律文書の両方の設定が前提です。                              |
| デバッグモード有効時に診断会話サマリーを保存 | オフ         | 文字数・コンテキスト状態・運用メタデータのみ保存。質問・回答本文は保存しません。                                                      |
| オプションの会話分析同意を提示               | オフ         | 訪問者がオプトインすると、PII・禁止ワードをマスクした質問・回答テキストをサービス改善のため保存します。拒否してもチャットは使えます。 |
| 会話ログの保存期間                           | 7日          | 診断サマリーとオプトイン分析ログの削除までの日数（1–365）。                                                                           |
| 失効した同意レコードの保存期間               | 180日        | 撤回・失効した同意レコードの削除までの日数（1–3650）。                                                                                |
| 必須規約/任意分析チェックボックスのラベル    | 内蔵テキスト | 各同意チェックボックスの横に表示する文言。                                                                                            |
| 同意画面のメッセージ                         | 内蔵テキスト | 通知文。`%s` プレースホルダーが規約・プライバシーのURLに展開されます。HTML可。                                                        |

タブには**現在の同意バージョン**のハッシュも表示されます。開示内容が変わるとこの値が更新され、訪問者に再度同意を求めます。保存内容の詳細は[プライバシーとデータの取扱い](privacy.md)を参照してください。

## 「詳細設定」タブ

### リランカー設定

「プロバイダー」タブでのCohere APIキー設定が前提です。

| フィールド                     | デフォルト | 範囲  | 説明                                                                   |
| ------------------------------ | ---------- | ----- | ---------------------------------------------------------------------- |
| リランカーを有効化（推奨）     | オン       | —     | 取得チャンクをCohereで並べ替えてからLLMに送ります。                    |
| LLMに送るチャンク数（上位N個） | `5`        | 1–20  | リランク上位N件のみをモデルに送信します。                              |
| 初期候補（ベクトル検索）       | `50`       | 5–200 | リランク前にQdrantから取得する候補数。                                 |
| ハイブリッド候補数             | `50`       | 5–200 | ハイブリッド検索時のソース別候補数。                                   |
| リランキングタイムアウト（秒） | `15`       | 1–60  | Cohereリクエストのタイムアウト。タイムアウト時は元の順序を維持します。 |

### Qdrant 設定

| フィールド                | 説明                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Qdrant エンドポイント** | Qdrant HTTP APIのベースURL（ポート含む）。例: `https://your-instance.qdrant.io:6333`                 |
| **Qdrant API キー**       | 暗号化して保存。空欄の場合は保存済みキーを維持します。                                               |
| **コレクション名**        | このサイトで使うコレクション名。コレクションのベクトルサイズはベクトル化モデルと一致させてください。 |

注意: Qdrant Cloudの**無料**クラスターでは、一定期間アクセスがないとコレクションが削除される場合があります。

クラスターとコレクションの作成手順（必要なベクトルサイズを含む）は[外部サービスのセットアップ](services.md)を参照してください。

### 日本語トークナイザー

サイトロケールが `ja` / `ja_JP` の場合のみ表示。キーワード（BM25）インデックスと検索のトークナイズに影響します。ベクトルDBのみを使う場合は使用されません。

- **エンジン**: `内蔵（TinySegmenter）`（デフォルト、PHP 8.0以上が必要）または `Yahoo! Japanese MA API`。PHP 8.0未満ではYahoo! MAが強制され、セレクターは無効化されます。
- **Yahoo! App ID**: 暗号化して保存。`wp-config.php` に `FE_SEARCH_AI_YAHOO_APP_ID` を定義するとそちらが優先されます。IDの取得方法は[外部サービスのセットアップ](services.md)を参照してください。

### 詳細設定

| フィールド                                 | 説明                                                                                                                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **同梱のプラグイン CSS を読み込む**        | デフォルト: オン。チャットUIをテーマのCSSだけで構成する場合はオフにします。                                                                                                  |
| **同梱のプラグイン JavaScript を読み込む** | デフォルト: オン。チャットUIのHTMLを独自実装に置き換えAPI通信も自前で処理する場合のみオフにします。                                                                          |
| **デバッグモード**                         | `{prefix}fe_search_ai_system_logs` に動作ログを記録します。トラブルシューティング時のみ有効化してください（パフォーマンスに影響します）。                                    |
| **ログ保存期間（日数）**                   | システムログを日次ローテーションで削除するまでの日数。デフォルト `30`、範囲1–365。                                                                                           |
| **検索トレースの永続化**                   | 検索品質分析用に検索トレース（クエリのハッシュ、投稿ID、ランキングスコア。質問・回答本文は含まない）を保存します。デフォルトはオフ。保持期間も設定可（デフォルト `30` 日）。 |

### 外部API（Pro）

「詳細設定」タブにProの2セクションが追加されます。

- **API Token Management** — `/query` とMCPエンドポイント用の名前付きBearerトークン（`fesai_tk_...`）の発行・失効。
- **MCP Integration** — コピー可能なMCPクライアント設定と公開ツール一覧。

セットアップとエンドポイントの詳細は[MCP連携](mcp.md)を参照してください。

### データ管理

破壊的なメンテナンス操作。各操作は明示的なボタンで実行します。

- **同期データの削除** — 全ベクトルとキーワードインデックスを削除。再同期するまでAI検索は動作しません。
- **システムログの削除** — `{prefix}fe_search_ai_system_logs` を空にします。
- **検索トレースの削除** — `{prefix}fe_search_ai_retrieval_traces` と `{prefix}fe_search_ai_retrieval_trace_items` を空にします。
- **会話ログの削除**（Pro） — `{prefix}fe_search_ai_logs` を空にします。
- **同意レコードの削除**（Pro） — 撤回・失効したレコードのみ、または `{prefix}fe_search_ai_consents` の全レコードを削除します。

### アンインストール時にデータを削除

有効にすると、アンインストール時にプラグインの全テーブルと設定を削除します。オフのままなら、再インストール時に以前の設定と同期データが残ります。

## セキュリティ（Pro）

Proライセンスが有効な場合、「セキュリティ」タブが表示されます。

### 禁止ワードリスト（Forbidden Words List）

カンマ区切りで禁止ワード・フレーズを登録します。一致箇所は訪問者の入力・AIの回答の**両方**で `[REDACTED]` に置き換えられます（大文字小文字を区別しません）。フィルターは `fe_search_ai_preprocess_user_question` / `fe_search_ai_preprocess_model_response` にフックされるため、Pro版のREST `/query` とMCPエンドポイントにも適用されます。リストはAES-256-CBCで暗号化して保存されます。

- 「ignore previous instructions」などの基本的なインジェクション用フレーズは内蔵の言語ファイルで常時フィルターされます（**View Default Security Filters** で確認可能）。カスタムリストへの追加は不要です。
- カスタムリストを空にすると、内蔵の英語フォールバックリストが使われます。
- プロジェクト名・社内用語・サイト固有のインジェクションフレーズの遮断に利用してください。

### APIレート制限（API Rate Limiting）

| フィールド                     | デフォルト           | 説明                                               |
| ------------------------------ | -------------------- | -------------------------------------------------- |
| ユーザーごとの制限（IPベース） | 50リクエスト/時間    | `-1` で無制限。                                    |
| サイト全体の制限（グローバル） | 1000リクエスト/日    | APIコストの暴走を防ぐ安全弁。`-1` で無制限。       |
| 管理者通知                     | 80%                  | グローバル上限のこの割合に達した時点でメール通知。 |
| 通知先メールアドレス           | サイトの管理者メール | しきい値通知の宛先。                               |

## システムログ画面（Pro）

Pro版では管理メニューの FE Search AI の下に「System Logs」サブメニューが追加されます。`{prefix}fe_search_ai_system_logs`（および会話ログ）をフィルタリング可能な一覧で表示し、**CSVエクスポート**ボタンでオフライン分析用に書き出せます。

## 暗号化

すべてのAPIキーとYahoo! App IDは `FE_Search_AI_Encryption_Helper` で暗号化されて保存され、リクエスト時のみ復号されます。
