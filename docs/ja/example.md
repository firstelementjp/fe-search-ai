# 例

代表的なサイト種別ごとの実践的な設定例です。各レシピは、プラグインのインストールと、最低1つのチャットプロバイダー・ベクトル化 AI・ストレージの設定が済んでいることを前提とします。

## ドキュメントサイト

ドキュメントページをインデックスして、訪問者が目次を探す代わりに質問できるようにします。

1. 「同期ターゲット」で `page` 投稿タイプ（またはドキュメント用CPT）を有効にし、タイトルと本文をチェックします。
2. ドキュメントがタクソノミーで整理されている場合は、関連タクソノミーをチャンクデータに含めます。
3. ドキュメントのトップページに `[fe-search-ai]` を追加するか、ドキュメント系の投稿IDのみでフローティングチャットを有効化します。
4. 「サイトの目的（AI）」にドキュメントの範囲（対象製品やバージョンなど）を記述します。
5. よくあるサポート質問トップ10を試し、システムプロンプトを調整します。

## 製品サポート

1. 製品ページ、FAQ、サポートドキュメントを同期します。
2. 「特定の記事を除外」で購入・アカウント系ページを除外します。
3. リランク（Cohere）を有効化します — 製品名は多くのチャンクに登場するため、リランクで適切なチャンクが浮上しやすくなります。
4. フローティングチャットをサイト全体に出し、カート・購入ページはIDで除外します。

## ナレッジベース

1. 記事用のカスタム投稿タイプを作成または再利用し、「同期ターゲット」で有効化します。
2. モデルが回答内でカテゴリを引用できるよう、タクソノミーを含めます。
3. 記事にカスタムフィールド（バージョン番号、適用範囲など）がある場合、Pro版でインデックスに追加できます。
4. 範囲を明確にするため、フローティングチャットではなくナレッジベースのトップページに `[fe-search-ai]` を設置します。

## 日本語サイト

1. 「詳細設定」タブで日本語トークナイザーが `内蔵（TinySegmenter）`（PHP 8.0以上）になっているか確認し、必要ならYahoo! MA API用にApp IDを設定します。
2. ハイブリッド検索を有効のままにします — BM25はベクトルが拾い損ねる完全一致を捕捉します。空白区切りでない日本語では特に重要です。
3. トークナイザー変更後は「インデックスを再構築」を実行します。
4. 自然言語の質問と完全一致の語句の両方を試し、重要な語句はタイトルや見出しに入れます。

## コストを抑えた導入

1. 「同期上限」（例: `50`）と「特定の投稿のみを同期する」でパイロット対象を絞ります。
2. 「インデックスを再構築」を実行し、回答品質を評価します。
3. 「要約から埋め込みを生成」は品質のため有効のままにするか、わずかなマッチング向上より同期コストを優先するならオフにします。
4. 「同期上限」を段階的に上げます。チャットのAPI使用量は組み込みレート制限（IPあたり50/時、サイト全体1,000/日）で既に上限があります。

## ショートコードとテンプレートタグ

```text
[fe-search-ai]
```

```php
<?php
if ( function_exists( 'fe_search_ai' ) ) {
    fe_search_ai();
}
```

## セットアップチェックリスト

- プロバイダーを設定する。
- データ保存先を選ぶ（WordPress DB、Qdrant、またはハイブリッド用に両方）。
- 同期対象を選択する。
- 「インデックスを再構築」を実行する。
- チャットUIを設置する。
- プロンプトをテストして調整する。
